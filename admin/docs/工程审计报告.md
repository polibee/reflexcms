## 五、能否投入生产？——结论

**当前状态：框架骨架达到生产级工程质量（构建、静态检查、权限执行、运行时全部验证通过），但作为"应用"尚不可直接上生产。**

阻塞项是**数据与会话层的 Demo 实现**，而非框架本身：

### 上生产前必须完成（P1）

1. **真实数据库替换内存仓储**：`server/utils/db.ts` 为种子内存实现（重启即失）。接口已隔离在 `getCollection/insertRow/updateRow/deleteRows/applyQuery` 之后，接 Drizzle/Prisma 不需动 API 层。
2. **真实鉴权替换演示会话**：`server/utils/auth.ts` 为内存 token Map + 演示账号。需换 JWT/OAuth/数据库会话；cookie 已是 httpOnly+sameSite=lax，生产还需加 `secure: true`。
3. **HTTPS 与部署加固**：Nitro 产物可直接部署 Node 环境/容器/Serverless；需前置 TLS、配置 `secure` cookie、限制 CORS 来源。

### 强烈建议（P2）

4. 测试基建：Vitest 单测（schemaToZod 编译器、can() 匹配器、applyQuery 查询引擎是三个最高价值纯函数点）+ Playwright 关键路径 E2E。
5. 速率限制与登录防爆破。
6. 补齐文档承诺字段：Upload / RichEditor / Repeater 表单控件、表格列显隐开关、Database Notification 层。
7. CI 流水线固定 `lint + typecheck + build` 三道闸门（本地基线已归零，脚本就绪）。

> 一句话结论：**作为框架底座可以开始承载真实业务开发；作为线上服务，完成上述 P1 三项后即可上线。**

**单测立即产生回报**：首个用例批次抓出一个此前所有冒烟测试未暴露的编译器缺陷——
`required` 的 `select`/`relation` 字段被误走字符串规则链，对 `ZodEffects` 调用 `.min()`
直接抛 `TypeError`（影响 posts 创建/编辑页的校验 Schema 构建）。
已重构 `compileField` 分支：字符串系（text/password/textarea/date）走 `.min()`，
email 走专用链，number 走 preprocess，select/relation 走 `refine` 空值拒绝。
该缺陷归档为 **P0-2**（功能阻断级），修复由回归测试锁定。
