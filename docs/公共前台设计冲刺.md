## 1. 三种站点模式的信息架构

### 博客模式（site.mode = blog）

```
导航: 首页 · 文章 · 分类 ▾ · 标签 · 关于
首页 = 文章流（按 published_at DESC，置顶优先）
路由:
  /                    → 文章列表（分页）
  /articles/:slug      → 文章详情 + 评论
  /categories/:slug    → 分类下文章列表
  /tags/:slug          → 标签下文章列表
禁用板块: 论坛全部路由不注册（404）
```

### 论坛模式（site.mode = forum）

```
导航: 首页 · 板块 ▾ · 热门 · 最新
首页 = 板块列表 + 各板块最新帖子摘要
路由:
  /                    → 板块索引
  /f/:slug             → 板块帖子列表（支持排序: 最新回复/热度/新建）
  /t/:id               → 帖子详情 + 楼层回复 + 最佳回复标记
禁用板块: 文章/分类/标签/评论路由不注册
```

### 共存模式（site.mode = hybrid，默认）

```
导航: 首页 · 文章 · 论坛 ▾ · 标签 · 关于
首页 = 双栏: 左侧文章流 + 右侧热门帖摘要
路由: 合并博客模式与论坛模式的全部路由
```

**正交轴**: mode 决定暴露哪些板块；theme（Nuxt Layer）决定长什么样。同一 mode 可搭配不同 theme。

## 2. 页面清单

| 页面 | 模式 | 数据来源（/api/v1） | SEO 要点 |
|---|---|---|---|
| 首页 | 全部 | site/config + articles?featured 或 topics?hot | canonical, OG |
| 文章列表 | blog/hybrid | GET articles?page&perPage | rel=prev/next |
| 文章详情 | blog/hybrid | GET articles/:slug + comments | meta description=summary, OG article |
| 分类页 | blog/hybrid | GET categories/:slug → articles?category_id= | canonical |
| 标签页 | blog/hybrid | GET tags/:slug → articles | canonical |
| 板块索引 | forum/hybrid | GET forums | — |
| 板块帖子列表 | forum/hybrid | GET topics?forum_category_id=&sort= | rel=prev/next |
| 帖子详情 | forum/hybrid | GET topics/:id + replies | title=title |
| 关于/关于我们 | 全部 | settings (site.about) | static |

## 3. API v1 契约（本轮冻结）

所有端点匿名可访问，按 `site.mode` 门控（被禁用板块返回 404）。

### 已实现

| 端点 | 响应 | 门控 |
|---|---|---|
| `GET /api/v1/site/config` | `{name, mode, seo{}, sections[]}` | 无（始终可用） |

### 待实现（后端已具备数据层，仅差路由注册）

| 端点 | 响应信封 | 门控 section |
|---|---|---|
| `GET /api/v1/articles?page&perPage&q` | `Paginated<ArticlePublic>` | articles |
| `GET /api/v1/articles/:slug` | `ArticleDetail`（含 content, comment_count） | articles |
| `GET /api/v1/topics?page&perPage&sort=latest\|hot` | `Paginated<TopicPublic>` | topics |
| `GET /api/v1/topics/:id` | `TopicDetail`（含 content, replies 前 N 条） | topics |
| `GET /api/v1/forums` | `Forum[]`（含 topic_count） | forums |

公共字段裁剪规则：
- Article 公开字段: id, title, slug, summary, cover, is_pinned, published_at, view_count, comment_count
- Topic 公开字段: id, title, status, is_pinned, is_featured, reply_count, like_count, view_count, last_reply_at
- **不含**: author_id, user_id（Phase B 登录后再关联作者昵称/头像）

### 门控中间件

```go
// /api/v1/{section}/** 统一挂载：
func Gate(section string) http.HandlerFunc {
    if !settingsservices.SectionEnabled(section) {
        return 404 // 对搜索引擎和用户均语义正确
    }
}
```

## 4. 主题（Nuxt Layers）结构

```
frontend/
├── nuxt.config.ts           # extends: themes/base + 当前激活主题
├── app/                     # 宿主壳
│   ├── pages/index.vue     # 按 sections 渲染对应组件
│   └── composables/useApi.ts # 基于 /api/v1 的 fetch 封装
├── themes/base/             # 类型、composable、布局骨架
│   ├── components/PageShell.vue
│   └── composables/useSiteConfig.ts
└── themes/blog/             # 博客主题层（首个交付主题）
    ├── app/pages/articles/[slug].vue
    ├── app/components/ArticleCard.vue
    └── app/layouts/BlogLayout.vue
```

SEO 基建在 base 层：useHead(title/description/canonical)、sitemap.xml 按 mode 生成。

## 6. Meilisearch 接入路径

当前 CJK 搜索降级为 ILIKE（顺序扫描），10k 行 p95=78ms 可用但不可扩展。
Search 接口已隔离在 `Spec.SearchOverride`——替换步骤：

1. 下载启动 Meilisearch（Windows 二进制 107MB，GitHub releases 可达但慢，建议用代理或离线传输）
2. Go 引入 `github.com/meilisearch/meilisearch-go`
3. 实现 `modules/search/meili.go`：索引同步（ArticlePublished→upsert）+ SearchOverride 替换
4. `.env`: MEILI_HOST、MEILI_KEY
5. ILIKE 兜底保留作为 Meili 故障时的降级路径
