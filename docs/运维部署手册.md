# 运维与生产部署手册

> 适用：ReflexCMS Full 产品（Blog/Forum 入口同理，替换二进制即可）。
> 配套：`deploy/backup.sh`（备份）、`scripts/contract-test.mjs`（部署后冒烟）、`docs/性能基线.md`。

---

## 0. 环境要求与准备

| 组件 | 版本 | 说明 |
|---|---|---|
| Go | ≥ 1.25 | 构建后端二进制 |
| Node.js | ≥ 20 | 构建/运行 Nuxt 前端（管理后台 + 公共前台） |
| PostgreSQL | ≥ 15（推荐 17） | 主数据库 |
| Redis | ≥ 6 | 缓存 / 频控计数 / 浏览量缓冲 |

创建数据库与账号（超级用户执行）：

```sql
CREATE USER reflexcms WITH PASSWORD '你的强密码';
CREATE DATABASE reflexcms OWNER reflexcms;
```

## 1. 环境变量清单（backend/.env）

| 变量 | 必须 | 说明 |
|---|---|---|
| APP_KEY | ✅ | 32 字符，`artisan key:generate` 生成 |
| JWT_SECRET | ✅ | `artisan jwt:secret` 生成（预留） |
| APP_ENV / APP_DEBUG | ✅ | 生产必须 `production` / `false` |
| APP_HOST / APP_PORT | ✅ | 后端监听地址端口 |
| DB_* | ✅ | PostgreSQL 连接五件套 |
| REDIS_* | ✅ | Redis 连接（CACHE_STORE=redis 时必需） |
| CORS_ORIGINS | Phase B | 逗号分隔前台白名单；为空则 CORS 关闭（BFF 同源无需） |
| SESSION_SECURE | 生产建议 | Cookie Secure 标记（admin BFF 侧另有 cookieSecure 随 NODE_ENV 自动开启） |
| ADMIN_EMAIL / ADMIN_USERNAME / ADMIN_PASSWORD | 可选 | `admin:bootstrap` 的账号参数；均可改用命令行旗标 |

前端（admin/.env）：

```
NUXT_PUBLIC_API_BASE=http://127.0.0.1:9000   # 浏览器可达的后端地址（或留空走同源 BFF）
cookieSecure=true                            # 由 NODE_ENV=production 自动开启
```

## 2. 构建与启动（手动部署全流程）

```bash
# ---- 后端 ----
cd backend && go build -o reflexcms-api .      # 单产品入口: go build -o blog-api ./cmd/blog
./reflexcms-api artisan migrate                # 数据库迁移（每次发版执行）
./reflexcms-api artisan db:seed                # 仅首次：角色等基础数据
./reflexcms-api artisan admin:bootstrap        # 超管引导（详见下节）
./reflexcms-api                                # 启动 API，默认 :9000

# ---- 前端 ----
cd admin && npm ci && npm run build
BACKEND_URL=http://127.0.0.1:9000 node .output/server/index.mjs   # 默认 :3000
```

健康检查：`curl http://127.0.0.1:9000/api/v1/healthz` 应返回 200（含 DB/Redis 探活）。

### 2.1 超级管理员引导（admin:bootstrap）

```bash
./reflexcms-api artisan admin:bootstrap                     # 全新安装：自动生成强密码，只打印一次
./reflexcms-api artisan admin:bootstrap --email=ops@example.com
./reflexcms-api artisan admin:bootstrap --email=ops@example.com --password='新密码'   # 重置已有超管密码
```

- **重复执行安全**：已存在超管且未提供 `--password` 时命令是 no-op（仅提示账号邮箱），可放心放进每次发版脚本。
- 备选路径：空站点上**第一个通过公开注册的账号**自动获得 super-admin 角色。
- 密码修改走后台「个人设置」（`PUT /api/v1/me/password`，需验证旧密码）。

### 2.2 systemd 托管（Linux）

```ini
# /etc/systemd/system/reflexcms-api.service
[Unit]
Description=ReflexCMS API
After=network.target postgresql.service redis.service

[Service]
User=reflexcms
WorkingDirectory=/opt/reflexcms/backend
ExecStart=/opt/reflexcms/backend/reflexcms-api
Restart=always
RestartSec=3
Environment=APP_ENV=production

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/reflexcms-web.service
[Unit]
Description=ReflexCMS Web (Nuxt)
After=network.target reflexcms-api.service

[Service]
User=reflexcms
WorkingDirectory=/opt/reflexcms/admin
ExecStart=/usr/bin/node .output/server/index.mjs
Environment=NODE_ENV=production
Environment=BACKEND_URL=http://127.0.0.1:9000
Environment=NUXT_PUBLIC_API_BASE=https://api.example.com
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

`systemctl daemon-reload && systemctl enable --now reflexcms-api reflexcms-web`。Windows 服务器用 NSSM 分别注册两个服务。

### 2.3 反向代理

Caddy（自动 TLS）：

```
api.example.com {
    reverse_proxy 127.0.0.1:9000
}
admin.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Nginx 等价配置：

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;
    location / { proxy_pass http://127.0.0.1:9000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $remote_addr; }
}
server {
    listen 443 ssl http2;
    server_name admin.example.com;
    location / { proxy_pass http://127.0.0.1:3000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $remote_addr; }
}
```

TLS 由反代终结；此时设置 `SESSION_SECURE=true`、admin 以 production 构建（`NODE_ENV=production` 自动开 Cookie Secure），并在后台「站点设置」把 APP_URL/站点地址填为公网 URL（支付回调 NotifyURL 依赖它）。

## 3. 备份

```bash
# 手动
PGPASSWORD=secret ./deploy/backup.sh

# 定时：crontab 每天 03:00
0 3 * * * PGPASSWORD=secret /path/to/reflexcms/deploy/backup.sh >> /var/log/reflexcms-backup.log 2>&1
# Windows 任务计划程序同理指向 Git Bash 执行
```

产出 `backups/reflexcms_YYYYMMDD_HHMMSS.dump`（custom 格式+压缩），默认保留 **14 天**（`RETAIN_DAYS` 可调）。

### 恢复步骤

```bash
psql -U postgres -c "CREATE DATABASE restored OWNER reflexcms;"
pg_restore -U reflexcms -d restored --no-owner backups/<dump 文件>
psql -U reflexcms -d restored -c "SELECT COUNT(*) FROM articles;"   # 行数核对
# 核对无误后切换：停后端 → 改 .env DB_DATABASE=restored → 启动
```

**演练记录**：
- 2026-08-25：`reflexcms_20260825_081227.dump`（1.5M）→ 还原至临时库 `reflexcms_restore_test`，核对 articles=10,023 / replies=100,080 与主库一致 → 已删除临时库。演练人：ox-alpha。

## 4. 上线检查单

- [ ] `APP_DEBUG=false`、`APP_ENV=production`
- [ ] `admin:bootstrap` 已执行且生成的超管密码已妥善保存（或已用 `--password` 设置强密码）
- [ ] Cookie Secure：backend `SESSION_SECURE=true`；admin 以 production 构建（cookieSecure 自动开）
- [ ] 反代 TLS 生效（http→https 跳转）
- [ ] `CORS_ORIGINS` 仅填真实前台域名
- [ ] 初始超管密码已修改（settings/users 页面）
- [ ] `./reflexcms-api &` 前执行过 `migrate` 且 `healthz` 双绿
- [ ] 备份任务已注册并手动跑通一次 + 恢复演练一次
- [ ] `node scripts/contract-test.mjs https://api域名` 全绿
- [ ] 日志目录（backend/storage/logs）有轮转（daily 驱动默认 7 天）

## 5. 安全机制一览（本里程碑落地）

| 机制 | 实现 |
|---|---|
| 登录限流 | IP 级 5 次/分 + 账号级连续失败 10 次锁 15 分钟 |
| 审计日志 | 所有 admin 变更（网关 CRUD + 发布/置顶/审核等动作）异步写 `admin_operation_logs`，敏感字段脱敏，后台只读可查 |
| SSRF 防护 | 出站请求统一 `support/safefetch`（白名单协议+私网拦截+重定向复检），封面外链强制校验 |
| SQL 注入 | 全部查询参数绑定；排序字段仅白名单/常量片段 |
| 密码存储 | bcrypt cost 12 |
