## 2. 注册限制实现

```
用户提交注册
  ↓
① reg.enabled = false → 403
② 邮箱域名 ∈ reg.email_blacklist → 422 "该邮箱域名不可用"
③ reg.email_whitelist 非空 且 域名 ∉ 白名单 → 422
④ reg.mainstream_only 且 域名 ∉ MAINSTREAM → 422
⑤ reg.turnstile_enabled → POST turnstile/siteverify 验证 token
⑥ 全部通过 → 创建用户
```

主流邮箱域名列表（MAINSTREAM）：gmail.com, outlook.com, hotmail.com, yahoo.com, icloud.com,
qq.com, 163.com, 126.com, sina.com, foxmail.com, proton.me, protonmail.com。

## 3. Hook / Filter 插件机制（设计，不排期）

基于已有的 kernel.EventProvider + settings KV，插件机制的三个原语：

| 原语 | 用途 | 实现载体 |
|---|---|---|
| **Action(Hook)** | 在特定时机执行副作用（发通知、写日志） | 已有：kernel.EventProvider + facades.Event() |
| **Filter** | 修改数据后再传递（如过滤评论敏感词） | 新增：`kernel.Filter` 接口 + 管道执行器；各模块在输出前调用 `filters.Apply("comment.content", content)` |
| **Provider** | 注册自定义路由/资源/服务 | 已有：kernel.Module |

**Filter 管道**（MVP 不实现，接口预留）：
```go
// kernel/filter.go（未来）
type Filter interface {
    Tag() string                    // "comment.content"
    Apply(value any, args ...any) any
}
// 使用方：content := filters.Apply("comment.content", rawContent).(string)
```
触发条件：出现真实的第三方扩展需求或 ≥3 个模块需要同一数据变换时再实现（同 ADR-009 触发逻辑）。

**Theme API**：前台主题 = Nuxt Layer 只消费 `/api/v1/**`（ADR-010），后端零感知。后台主题 = CSS 变量令牌，延后。
